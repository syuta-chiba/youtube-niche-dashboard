⚙️ 観測の仕組み

← ダッシュボードへ戻る2026-10-27 時点の構成

YouTube の AI・開発系チャンネルを「見つける → 貯める → 巡回する → 張り付く」の4段で観測している。すべて GitHub Actions の cron で動くので、PC を閉じていても回り続ける。収集はこのダッシュボードと同じ public リポジトリ youtube-niche-dashboard で動いている（2026-10-27 に private から移設。public は Actions が無料）。

① 見つけるキーワード検索で新しいchを拾う
② 貯める見つけたchを全部プールに残す
③ 巡回するプール全員を毎朝RSSで見回る
④ 張り付く注目chを1日4回細かく観測
＋
⑤ 全動画DB外れ込みで全動画を貯める（初回取得待ち）

各段の集め方

① 見つける（発見）一時停止中

キーワードで YouTube を検索して、まだ知らない同規模のチャンネルを拾う入口。

いつ毎日 JST 04:23（発見ループ）／ JST 14:20（余った quota で試験語検索）
どうやって discovery_keywords_tech.txt の約34語（Claude Code・Codex・Ollama・LM Studio など）で search.list を叩く → 登録者 50〜2,000 のchを候補に → 各chの直近150本を videos.list で取得 → 広告で盛られた疑いの動画を除外 → 「普段（再生数の中央値）の5倍以上」跳ねた動画が2本以上あり、直近90日にも波があるかを判定。
試験語検索は、その日に余った quota で新しい語を1回だけ検索し、使った語は二度と検索しない。
コスト重い。検索1回 100 unit（1日の無料枠は 10,000）。発見ループだけで1日 約4,700〜5,300 unit 使っていた
出口全条件を満たしたchは「✅ 全条件クリア」タブに並ぶ。注目chへの追加は人間が決める（自動では追加しない）
状態2026-10-26 から検索を一時停止（広告判定に quota を回すため）。手動実行はできる

② 貯める（候補プール）稼働中

一度でも視界に入ったチャンネルを、合否に関係なく残し続ける場所。

どうやって①で評価したch・検索に出たch・外部HITコーパスに出たchを rss_pool.json に追記。消さない
規模3,442 ch（2026-10-27）
あわせて貯まるもの 外部HITコーパス external_hits.jsonl：①③で見つけた「当たった動画」。上限5,000件に達していて、古いものから捨てている
各chの登録者数の推移（毎日1回、50chで1 unit）
出口「🗂 発見済みch」タブ（登録者・前月比・再生中央値）、「🏆 当たり事例」タブ

③ 巡回する（RSS巡回）稼働中

プールの全員を毎日見回って、跳ねた動画を拾う。一度条件から落ちたchも見続ける。

いつ毎朝 JST 05:03
どうやって各chの RSS フィード（YouTube 公開の XML、最新15本）を読む → フィード中央値の5倍（下限500v）を超えた動画だけ API で確認（長尺か・like率0.4%以上か・登録者数）→ 通過分を外部HITコーパスへ。読んだ15本の再生数は動画ごとの日次系列として rss_video_series.jsonl に残す（伸び方の形で広告を見分ける用）
コストほぼゼロ。RSS は quota を使わない。API確認は跳ねた動画だけ数 unit（1日 約75 unit）
限界最新15本しか見えない。検索はできない。過去の外れ動画は取れない

④ 張り付く（注目chの定点観測）稼働中

真似元・手本として選んだ少数のchを細かく追い、動いた瞬間に知らせる。

いつ1日4回（JST 3・9・15・21時ごろ）
対象priority_channels.txt の12ch（戒くん・Sura・AIの歩き方・茶々丸・reck・デジタルの時間 など＋自ch）。広告混ざり枠 boosted_channels.txt の2chは別建てで観測
どうやって各chの全動画を playlistItems.list + videos.list で取得し、再生数・like・登録者を時系列で time_series/ に保存
コスト1chあたり約10 unit／回（1日 約340 unit）
出口Slack通知：🚨 新作検知／⚡ 初速検知（公開1〜2日で500v or 7日以内に700v）／🚀 急伸検知（1,000v or 登録者の2倍）／🎯 本命検知（普段の5倍＋広告疑いなし＋他chでも同テーマが当たっている）。急伸時は YouTube 全体で同テーマの当たり率も測る（市場検証・1本100 unit）。
ダッシュボード：チャンネル別タブ・🔥 急伸ウォッチ・🌱 検索資産

⑤ 競合全動画DB 準備完了・初回取得待ち

プールの各chについて、当たった動画だけでなく外れた動画も含めた全動画を貯める倉庫。

なぜ要るか①〜③で貯まるのはほぼ「当たり」だけ。外れの本数が分からないので、「このテーマは何本出て何本当たったか（当たり率）」が出せない
どうやって初回だけ各chの全履歴を取得（backfill、1ch 約8 unit、全体で約16,000 unit を数日に分割）→ 以後は RSS で新着だけ追記（quota ほぼ0）。保存先は このリポジトリの corpus/
できるようになることテーマ別の当たり率（外れ込み・95%信頼区間つき）、各chの普段・当たり・外れの全体像
状態2026-10-27 に保存先を このリポジトリの corpus/ に変更（鍵が不要に）。新着の追記は毎日自動。過去の全履歴は手動で backfill を実行して取り込む

この網の死角

入口がキーワードなので、キーワードにない分野は最初から見えない。

今のキーワードは IT・開発系だけ。たとえば AI×生命科学（AlphaFold・タンパク質設計・AI創薬）は、プール3,442ch中で関係するタイトルが2本しかない。「同じ好みの人がどこにどれくらいいるか」を測るには、①のキーワードを広げて網を張り、⑤で外れも含めて数える必要がある。

あわせて残っている宿題

  • ⑤の初回の全履歴取得（backfill・約16,000 unit）を手動実行する
  • 外部HITコーパスの上限5,000件で古いものを捨てている問題
  • プール3,442chの「調査対象に入れるか」の振り分けが全件未判定
